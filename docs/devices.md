# 장치 동작

현재 구성은 **2026-10-16 발주 기준: 10.1인치 IPS 터치 LCD(1024×600, mini HDMI·USB-C 터치), ReSpeaker Lite Voice Assistant Kit(보드+밀폐형 스피커), PCA9685 OE=GND**입니다. GPIO OE·HC125 배선은 사용하지 않습니다. 부품은 아직 도착 전이며(LCD 11/3, 음성 키트 11/4 예정) 터치 입력 처리는 구현하지 않았습니다.

화면·음성·귀 제어가 실제로 어떤 단위로 동작하는지 정리합니다. 전체 프로그램 구조는 [구현 개요](architecture.md), 실행 명령은 [모의 실행과 문제 해결](running.md)에서 확인합니다. 설정값은 구현 기준이며 실물 측정값과 구분합니다.

## 화면

- 디자인 좌표는 가로 **1024×600**이며, 실물·모의 기본 회전은 `0`도, 글꼴 크기는 36입니다. `90/180/270`도도 회귀 검사 가능한 선택 설정입니다. OS가 이미 화면을 회전했다면 앱 설정과 중복 적용하지 않습니다.
- `idle`, `listening`, `processing`, `speaking`, `awaiting_answer`를 눈·입과 상태 안내로 표현합니다. `succeeded`, `failed`, `unknown`은 업무 결과에 따른 얼굴 상태로 표시합니다.
- 한글 안내는 표정과 구분된 텍스트 화면에 표시합니다. 글꼴과 크기를 설정할 수 있으며, 화면을 넘는 긴 문장은 조용히 잘라내지 않고 `DISPLAY_TEXT_TOO_LONG`으로 거절합니다. 파이프라인이 짧은 문구를 다시 보내야 합니다.
- 화면 교체에는 증가하는 `revision`을 사용합니다. 이미 지난 번호는 `STALE_OUTPUT`, 표시 전에 새 출력으로 교체된 요청은 `SUPERSEDED`로 처리해 늦은 응답이 최신 화면을 덮지 않도록 합니다.
- `display.displayed`는 렌더러에 프레임을 제출했다는 보고입니다. 사용자가 실제로 읽었거나 패널이 정상 발광했다는 확인은 아닙니다.

## 마이크와 스피커

마이크 기본 입력은 **16kHz·모노·16비트 PCM**입니다. 20ms마다 320개 표본, 즉 **640바이트**를 전달하며 캡처 ID·순번·타임스탬프가 붙습니다. 타임스탬프는 호스트가 프레임을 읽은 시점이며 마이크 ADC의 정밀 표본 시각은 아닙니다.

스피커는 전달받은 PCM의 형식에 따라 **8–48kHz·1/2채널·s16le**를 지원합니다. 하나의 재생 job 안에서는 형식을 바꾸지 않습니다. 재생 장치 준비(`begin`), 데이터 제출(`write`), 재생 소진 대기(`finish`), 중단(`stop`)이 분리돼 있습니다.

| 상황 | 프로그램의 처리 |
| --- | --- |
| `begin` 성공 | 장치를 준비한 상태. 음성이 모두 재생됐다는 뜻은 아님 |
| `write` 성공 | 제한된 대기열에 PCM 수락. 아직 재생 중일 수 있음 |
| `finish` 성공 | 수락된 PCM과 장치 재생 버퍼가 모두 소진된 뒤 반환 |
| 재생 취소·장치 오류 | `audio.cancelled` 또는 `audio.failed` 보고. `audio.completed`로 처리하지 않음 |
| 마이크 프레임 유실·ALSA overrun/underrun | 스트림 오류 보고. 파이프라인이 해당 발화를 무효화하고 새 캡처를 시작해야 함 |

재생 중 녹음을 유지합니다. AEC(스피커 소리의 마이크 유입을 줄이는 반향 제거)와 VAD는 이 패키지에 포함되지 않으므로 동시 입출력 성공만으로 음성 인식 품질을 판정할 수 없습니다. ReSpeaker Lite 기준 출력 변환·음량 상한·입력 epoch 계약은 [통신 계약](protocol.md#current-audio-contract--2026-10-13)을 따릅니다.

## 귀 동작

PCA9685의 기본 I2C 주소는 **`0x40`**, 좌우 채널은 **0/1**, PWM 주파수는 **50Hz**입니다. `neutral`(중립), `perk`(귀 세우기), `droop`(내리기), `wiggle`(짧은 흔들기)을 제공하고, 좌우 정규화 위치도 전달할 수 있습니다.

좌우마다 `minUs`, `neutralUs`, `maxUs`, `inverted`를 따로 저장합니다. 실물 기본값의 1400–1600µs는 보정 시작용 예시이며, 실제 기구의 안전 범위를 측정한 값이 아닙니다. 프로그램은 1000–2000µs 밖의 펄스를 거절하고 기본 20µs 단위로 이동합니다.

실물 설정은 `calibrated: false`입니다. 정상 동작의 `motion.enable`은 보정 완료 전 거절합니다. 사용자가 명시적으로 여는 별도 보정 세션에서는 중립과 범위를 단계적으로 확인할 수 있으며, 결과를 `local.calibrated.json`에 저장하고 출력을 비활성화합니다.

OE는 GND에 고정합니다. 초기화 첫 쓰기부터 PWM FULL_OFF를 설정하고, 보정·명시적 활성화 때만 CH0/CH1의 FULL_OFF를 해제합니다. 정상 종료, 제어 연결 단절·만료, 검출된 모션 오류에서 차단을 시도하고 차단 실패도 오류로 보고합니다. **강제 종료나 커널 정지에서의 전기적 차단까지 보장한 것은 아니며 실측이 필요합니다.** SG90에 위치 센서가 연결되지 않았으므로 `motion.commanded`에는 `positionVerified: false`를 보고합니다.

## 설정

[모의 설정](../config/mock.json)과 [Jetson 설정](../config/jetson.json)을 구분합니다. 실물 설정은 귀 보정 전 비활성 상태이며 USB 오디오 ID와 I2C 버스는 진단 후 입력합니다. 배선·전원·OE 회로의 상세 설명은 [Jetson 설치](jetson-setup.md)에 있습니다.

## 남은 확인

실물 마이크·스피커의 음질·지연·반향, 좌우 귀의 중립·끝점·방향, 부팅·강제 종료·커널 정지에서의 PWM 출력은 측정이 필요합니다.
