# 검증 기록과 실물 확인 절차

## 소프트웨어 검증

**이 아래 2026-10-12 표는 당시 구현의 과거 기록이다.** 1024×600 화면·ReSpeaker·FULL_OFF·입력 게이트 변경의 검증은 아래 2026-10-13 항목을 따른다. 파이프라인 문서에는 10월 12일 Swift 매핑 작성 및 C++20 JSON/string 비교 빌드 실패가 별도 기록돼 있다. 이번 변경은 비교 타입을 명시했다. 당시 성공 기록으로 이후 빌드 실패를 덮지 않는다.

2026-10-12에 다음 검증을 실행해 통과했습니다. 아래의 모의 통신 시험은 실제 USB 오디오·PCA9685를 사용하지 않습니다.

| 환경 | 실행 결과 |
| --- | --- |
| macOS ARM64, AppleClang 15, Swift 5.10 | C++·SDL·Swift 빌드 성공. C++ core 및 통합 검사 통과: 통합 16개 중 15개 성공, Linux 전용 1개 제외. Swift 왕복 포함 |
| Ubuntu 22.04 ARM64 컨테이너, GCC 11 | ALSA 1.2.6.1·libgpiod 1.6.3·SDL2_ttf 2.0.18 실제 드라이버 빌드 성공. C++ core 및 통합 16개 모두 통과 |
| Linux Swift 6.0.3 | strict concurrency 및 warnings-as-errors 빌드 성공. XCTest 4개 통과 |
| macOS·Linux SDL 소프트웨어 렌더러 | 각 16개 화면 생성. 한글·텍스트 길이 거절·0/90도 회전 검사 통과. macOS 출력 이미지를 직접 확인 |
| macOS 독립 통합 데모 | 정상·스피커 오류 주입 두 경로 완료. 동시 캡처, 텍스트 대체, 질문 대기 15초 종료, 예약 알림, 텍스트 15초 복귀 확인 |

macOS에서는 Command Line Tools 환경에 XCTest가 없어 Swift 단위 검사를 실행하지 않았습니다. 해당 검사는 Linux에서 실행했습니다. Linux 검증은 ARM64 가상 머신 안의 Ubuntu 컨테이너에서 수행했으며 실제 Jetson의 커널·핀mux·그래픽 세션을 검증한 결과는 아닙니다. 검증용 가상 환경은 작업 후 제거했습니다.

테스트는 다음 동작을 검증합니다.

- 프로토콜 프레임 분할·병합, 한글과 바이너리 PCM, 길이 제한, 64비트 타임스탬프.
- PCM 형식·프레임 경계, 빈 재생 job 거절, 완료 이전 버퍼 drain, 재생 중 취소.
- 캡처·재생 동시 실행, 프레임 순서, WAV EOF와 마지막 프레임 패딩.
- 서버 스피커 큐 포화와 클라이언트 캡처 큐 포화, 마이크 단절 오류와 새 스트림 복구.
- 오래된 화면 출력 거절, 화면·음성 오류 분리, 텍스트 fallback용 화면 복구.
- 귀 보정 게이트, 좌우 반전·펄스 범위, 서보 오류·연결 종료·heartbeat 만료 후 비활성화.
- 단일 제어 연결, 중복 commandId 거절, 잘못된 패킷 후 재연결.
- Swift 예제의 화면·음성·귀 제어와 재생 중 마이크 프레임 수신.
- Linux 실제 모드의 장치 누락 오류. 장치가 없을 때 모의 성공으로 자동 전환하지 않음.
- 실제 ALSA API의 null 플러그인 재생. USB 스피커 성능 검증과는 별개.

실행 방법은 README와 `tools/check-linux.sh`에 있습니다. GUI 없는 CI에서는 `tests/visual.py`가 SDL dummy video backend로 **제품과 같은 렌더링 코드**를 실행합니다. 광학적 패널 확인은 아닙니다.

## 남아 있는 통합 경계

실제 팀 Swift 저장소의 protocol 적합성, STT/VAD/AEC, TTS가 내보내는 PCM 형식, 모델·업무 API는 이 패키지 단독 테스트의 대상이 아닙니다. 팀 파이프라인에 연결할 때 DTO 변환과 타이머 소유권을 확인하고 동일한 출력 ID로 성공·실패를 반영해야 합니다.

## 팀 파이프라인 연결 합격 기준

2026-10-12에 Swift 화면 매핑 함수를 실제 패키지 모듈로 타입 검사해 통과했고, 소켓 JSON 예제는 SDL 모의 서버에서 표시 성공·ID·revision을 확인했습니다. 활동 5종·결과 3종·한글 대체 문구·잘못된 활동값 거절도 확인했습니다. 아래 항목은 팀 파이프라인에 연결한 뒤 추가로 확인할 기준입니다.

- 성공·실패·결과 미확인 각각이 [표정 명세](https://github.com/hansung-capstone-team-8-new-line/knowledge/blob/master/wiki/deskpet-display-interface.md)의 매핑대로 표시되는지 확인한다.
- 답변을 만드는 동안 `processing`, 실제 재생 시작 뒤 `speaking`이 되는지 확인한다.
- 일반 응답과 재질문을 구분하고 질문 재생 완료 후에만 `awaiting_answer`로 바꾸는지 확인한다.
- 음성 실패 후 같은 ID·같은 업무 결과의 짧은 텍스트를 보내는지 확인한다.
- 텍스트 타이머가 끝나기 전에 새 요청이 오면 예전 타이머가 새 화면을 지우지 않는지 확인한다.
- 모델이 `cheerful` 또는 모순된 결과·감정을 내보내도 연결 검증에서 허용 값과 일관된 조합으로 바꾸는지 확인한다.
- 실제 팀 타입을 하드웨어 `OutputEvent`로 변환하는 래퍼가 컴파일되는지 확인한다.
